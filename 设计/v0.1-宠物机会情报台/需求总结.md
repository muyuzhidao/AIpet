# 宠物机会情报台 需求总结

版本：v0.1  
日期：2026-06-20  
模块名：宠物机会情报台  
参考产品：https://aihot.virxact.com/

## 1. 背景

线上宠物品牌老板和宠物初创公司需要持续观察新品类、新产品和用户需求变化。当前信息分散在抖音、小红书、微信公众号、Reddit、X、独立站、新闻门户等渠道里，单靠人工浏览很难每天稳定发现可行动的机会。

本模块做一个本地运行的内部情报后台，每天手动更新一次，将多源内容聚合成“今日机会流”，帮助用户快速判断哪些宠物行业机会值得进一步验证。

## 2. 目标用户

- 线上宠物品牌老板
- 宠物行业初创公司创始人
- 负责新品方向、内容调研、机会判断的小团队成员

## 3. 核心目标

首版只聚焦一件事：发现线上宠物行业里值得进一步验证的新产品 / 新品类机会。

机会判断以 A 为主，B 和 C 为辅助：

- A. 新品类 / 新产品机会：发现正在冒头的需求、痛点、用品形态、配方方向
- B. 内容和流量机会：发现内容爆点、平台讨论热度、传播角度
- C. 竞品和卖点机会：发现用户吐槽、选择空白、话术缺口

## 4. 首版范围

### 4.1 做什么

- 今日机会流：每天手动更新，展示 AI 简报和机会卡片
- 机会详情：展示机会评分、需求证据、增长信号、竞品空白、可行动性、原文链接
- 机会池：收藏、打标、备注、状态沉淀
- 数据源管理：配置来源、启停状态、关键词组、最近更新和失败原因
- 中英并列摘要：海外内容卡片显示中文摘要，详情页保留原文证据
- 部分失败可用：某些来源失败时，其余来源仍然生成今日机会流

### 4.2 不做什么

- 不做登录和权限
- 不做多人身份区分
- 不接电商 / 商品 / 销量 / GMV / 库存 / 价格数据
- 不做自动投放、自动选品、自动建站
- 不做市场规模预测
- 不做登录态抓取和私域数据获取

## 5. 关键决策

| 事项 | 决策 |
|---|---|
| 产品载体 | 本地运行的宠业信息站原型 |
| 主场景 | 今日机会流 |
| 页面方向 | 参考 AI Hot 的时间流信息站，分为精选、全部宠业动态、AI 日报 |
| 视觉风格 | 复刻 AI Hot 的清爽浅色阅读结构，内容改为宠物行业 |
| 数据更新 | 手动点击“开始更新” |
| 数据源 | 国内内容源、海外社区源、新闻/独立站内容源都覆盖 |
| 数据深度 | 中等分析：标签、机会分类、AI 摘要、竞品/痛点/需求提取 |
| 机会池 | 全局共享，不区分用户 |
| 部署 | 先跑在本机 |

## 6. 信息架构

首版 3 个主模块：

| 模块 | 作用 |
|---|---|
| 精选 | AI 从全量动态中筛出重点机会，并写推荐理由 |
| 全部宠业动态 | 按时间流展示全量宠业内容和品牌动态 |
| AI 日报 | 用日报形式总结今天最重要的宠业变化和判断 |

## 7. 主界面结构

主界面改为信息站结构，直接参考 AI Hot：

- 左侧：轻导航，直接进入精选、全部宠业动态、AI 日报
- 顶部：今日状态、搜索、来源筛选、开始更新按钮
- 精选：今日热点 TOP 3 + 精选卡片流，每条都包含 AI 推荐理由
- 全部宠业动态：按时间流展示全量信息，适合继续下翻
- AI 日报：用一版日报把当天的重要结论讲清楚

## 8. 机会评分

总分 100 分，4 个维度各 25 分：

| 维度 | 看什么 |
|---|---|
| 需求强度 | 用户痛点、反复提及、求推荐、吐槽 |
| 增长信号 | 最近出现频率、跨平台扩散、热度上升 |
| 竞品空白 | 内容里提到“买不到、不好用、选择少”等缺口 |
| 可行动性 | 是否能形成具体产品方向或验证动作 |

## 9. 机会池状态

| 状态 | 含义 |
|---|---|
| 新收藏 | 看到有价值，先收进池子 |
| 待验证 | 准备进一步查证需求或可行性 |
| 观察中 | 暂时不做，但持续关注 |
| 已否定 | 判断不适合做 |
| 已转项目 | 已决定进入产品/选题/调研动作 |

## 10. 数据更新流程

1. 用户点击“开始更新”
2. 系统从平台 API、Tavily、定向抓取源获取内容
3. 清洗、去重、按相似主题聚合成机会
4. AI 提取需求证据、增长信号、竞品空白、可行动性
5. 生成今日机会流，并记录失败的数据源
6. 高价值机会可收藏进机会池

## 11. 数据源与技术约束

| 来源 | 首版处理方式 | 约束 |
|---|---|---|
| 抖音 | 按用户已有 API 或第三方服务接入 | 官方开放平台能力更偏 OAuth、账号、发布、小程序等场景，是否可做全网内容检索需逐项确认 |
| 小红书 | 按用户已有 API 或第三方服务接入 | 官方开放能力偏电商、广告、分享、商家场景；公开笔记检索能力需按具体 API 确认 |
| 微信公众号 | 按已有服务或抓取源接入 | 官方公众号接口主要面向已授权公众号管理，不等同于全网公众号文章搜索 |
| Reddit | 官方 API / OAuth | 需要遵守 Reddit Developer Terms 和 API 访问限制 |
| X | X API v2 Search / Recent Search / Filtered Stream | 具体历史范围、频率、字段和价格取决于账号权限 |
| Tavily | Search / Extract / Research | 适合新闻、独立站和补充搜索；需要记录额度与失败状态 |
| 独立站 / 新闻门户 | Tavily 优先，必要时定向抓取 | 遵守 robots.txt、站点条款和访问频率限制 |

## 12. 页面状态

必须覆盖：

- 正常态
- 加载态
- 空态
- 筛选无结果
- 部分可用
- 全部失败
- API key 失效
- Tavily 超限
- 定向抓取失败
- 长文本截断
- 大量数据滚动

## 13. 验证标准

首版设计完成后，以以下标准验证：

- 本地可以打开主界面设计稿
- 页面能看出 AI Hot 式的左侧导航 + 主内容时间流结构
- 精选区包含 AI 推荐理由
- 全部宠业动态区能看出按时间排列的全量流
- AI 日报区能完整展示当日总结、重点章节和历史日报入口
- 全状态设计参考覆盖正常、加载、空、无结果、错误、部分可用和边界情况
